# 0.2.2 限流與重試修正

日期：2026-11-03。修正與合成測試完成，尚未提交 Chrome Web Store。

使用者提供的 174 則錯誤統計：冷卻 127、限流 2、無內容 35、影片預覽未取得 3、不支援圖片 2、超過 12 張圖 1、向量圖片無法轉換 4。主因是限流／冷卻被視為不可恢復錯誤；不是色情分類結果。

- 所有分頁共用每 65 秒 15 單位的本機排程，先確認容量，再下載圖片；工作階段計數可跨背景服務重啟保留。
- 冷卻與暫時連線失敗維持隱藏，自動重試；連續限流延長等待至最多 30 分鐘，不提高後台額度。
- 空內容、尚未載入圖片及無影片預覽分開計為等待內容，頁面載入後自動檢查。
- 設定頁顯示等待額度／等待內容與固定錯誤分類，不顯示任何原文或圖片。
- 保留正式版安靜隱藏；不支援格式、圖片過多等問題仍需另行處理，不宣稱全部 174 則都能分析。

本次沒有 Chrome 操控工具，無法對使用者的實際 Facebook 分頁驗收。本機沙箱無法啟動隔離 Chrome，瀏覽器情境交由 GitHub CI 的合成頁面測試。

驗證：本機 17 項限流／背景／服務客戶端測試通過；[GitHub Actions](https://github.com/Wolke/fb-content-guard/actions/runs/41590560818) 的完整邏輯測試、Worker／D1 runtime、套件驗證及瀏覽器合成情境全部通過。正式版與開發版 ZIP 已產生，尚未安裝至使用者 Chrome。

限制：後台仍保留全站每分鐘 15／每日 1,000、單一 IP 每日 200、匿名 session 每日 100 單位。圖片每張算一單位，純文字至少一單位；排隊不會增加每日容量。GitHub CLI 登入失效（HTTP 401），目前僅透過 Git SSH 推送修正分支，尚未建立 PR 或合併 main。
