# 0.2.4 — 可選本機圖片加強檢查

狀態：程式已推送至公開 GitHub，隱私政策網站已部署；完整 CI 通過。Google 身分驗證完成，0.2.4 正式套件已上傳並提交審查，控制台顯示「待審查」，未變更正式雲端後台。

## 行為

- 預設關閉；開啟擴充功能模型分頁、下載／啟用 Gemini Nano 後，於 popup 勾選並儲存。
- 雲端判定 allow 的圖片貼文再逐張檢查；只接受 JSON Schema 約束的 ALLOW / BLOCK / UNCERTAIN，全部圖片通過才顯示。
- 不增加 Chrome 權限。Prompt API 在獨立的可信任擴充功能分頁執行；必須保留該分頁。
- 文字與原本圖片仍需雲端同意與額度，本機檢查不增加雲端配額；不是離線模式。
- 關閉模型分頁、取消、逾時、不確定、無效回覆與 context overflow 全部保持隱藏。
- 設定改變會清除快取、取消舊請求，防止舊放行結果繞過新設定。
- 隱私政策來源與商店說明已更新。公開政策回傳 HTTP 200，內容逐位元與本機來源一致（SHA-256：2ece465a4d20fbf71e9af8b287879b20739b0bf766b64c4c26096e62453111b1）。

## 驗證（2026-11-04）

- `npm test`：51/51 通過，含背景雲端→本機判斷流程、外來 port 拒絕、取消、斷線、逾時、多圖與無效結果。
- 真實 Chrome 156、公開 Prompt API，執行本次 `local-model.js`：使用者提供的廣告照片縮至 512px，回傳 block，耗時 27,033ms。

- 真實 Chrome 中的合成動態牆：7 項可見性／設定切換檢查通過，包括舊請求延遲 allow 不會露出內容。測試只改寫 content.js 的主機判斷以在 about:srcdoc 執行，分類傳輸採模擬。
- 語法檢查與 ZIP 完整性驗證通過；正式包維持無診斷卡，開發包有診斷卡。
- 完整 Playwright suite 已於 GitHub CI 執行並通過 32 項情境。真實 Facebook → 雲端 → 擴充功能模型分頁已觀察到推論及不確定回傳，但成功分類／放行仍未完成驗收（見下方實測紀錄）。
